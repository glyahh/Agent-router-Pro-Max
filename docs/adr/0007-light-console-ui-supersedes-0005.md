# 控制台改为浅色留白风格，取代 0005 的深色高密度

> **2026-09-30 补充**：另有一套**跟随系统的深色主题**（[0010](0010-dark-theme-follows-system.md)），
> 系统深色时用它。本 ADR 定的浅色设计在浅色系统下**仍然有效、一位没改**；
> 两套主题共用同一份令牌名，只换值。

`docs/adr/0005-dark-high-density-console-ui.md` 定的是深色高密度极客风：纯黑底、等宽字体承载
一切、`//` 分区注释、方括号 chip、47px 网格纹理。用户在本轮要求改成"清新高级感"，参考 ChatGPT
官方界面。**这是一次决策反转**，记在这里；0005 已标记为 superseded，不要照着它改样式。

## 改了什么

- `:root` 全量换成语义令牌：白底 / 近黑文字 / hairline 分隔 / 近黑强调色 / 浅底状态药丸
- 去掉网格纹理、圆点霓虹光晕、`//` 注释装饰、全站等宽、大写加字距的小标签
- **等宽只留给真正的数据**（模型 ID、路径、日志、数值），并配 `font-variant-numeric:tabular-nums`
  保住数字对齐。原来靠"全站等宽"顺带解决的对齐问题，现在由 tabular-nums 解决
- 圆角 7px→12px（卡片）、10px（控件）、999px（药丸）；主内边距 26/24px→32px；行高与控件整体放大
- 状态色保留语义、压低饱和、改成浅底药丸：`ACTIVE`/`IDLE`/`WARN` 仍然一眼可辨
- 表格数字列仍走等宽，避免列宽跳动

## 代价（写清楚，别只记好处）

1. **信息密度下降。** 0005 的核心卖点是"同屏放更多可扫数据"；换气之后配置页一屏放不完三列模型
   列表，要滚动。这是自觉取舍：用户要的是观感，不是密度。
2. **浅色底对状态色的对比度更敏感。** 深色底上 `#22C55E` 很亮；白底上必须压到 `#0F7B52` 才够
   AA。所有状态色重新取过值，不是照搬。
3. **顺手删掉了 `config.js` 里约 110 行重复的设计系统。** 浅色化时发现改 `:root` 传不到配置页
   ——它把 `.stitle` / `.btn` / `.picks` / `table.t` 等整份复制，靠更高权重覆盖。删掉重复后
   `config.js` 净减 4.6 KB，设计系统重新只剩 `app.css` 一份。**以后加页面不要复制设计系统。**
4. `main.py` 里"控制台端口被占"的兜底页自带一套内联深色样式，不在设计系统覆盖范围内，本轮手工
   一并改浅。它是**唯一**一处设计系统之外的颜色，改主题时别忘了它。

## 踩到的坑：通用 `input` 规则会把复选框带崩

浅色化后第一版**上线即坏**：模型列表里每个复选框被拉成整行宽的近黑药丸，模型名被挤出可视区。

根因是**权重打平 + 注入顺序**：

- `app.css` 的 `.pick input{width:15px}` 权重 `(0,1,1)`
- 页面自行注入的 `.cfg select,.cfg input,.cfg textarea{…width:100%…}` 权重也是 `(0,1,1)`
- 而页面的 `<style>` 是运行时 `appendChild` 到 `<head>` 的，**排在 `app.css` 之后** → 同权重时后者赢
- 于是 `width:100%` 落到复选框上；`--accent` 是近黑，`input:checked` 就把整行涂黑了

**修法（已落地）**：两处通用规则都加 `:not([type="checkbox"])` 封住，从源头堵掉这类碰撞，
而不是在 `.pick` 上再加一条更高权重的补丁：

```css
/* app.css */
.f input:not([type="checkbox"]),.f select,textarea.inp{…}
/* 页面注入的样式 */
.cfg select,.cfg input:not([type="checkbox"]),.cfg textarea{…}
```

**教训**：这个项目里"页面注入的 CSS 排在 app.css 之后"是一条**隐蔽的优先级规则**。
任何页面级通用选择器（`input` / `select` / `a` / `td`）都可能悄悄盖掉 `app.css` 的同权重规则。
写页面样式前先想清楚会不会命中共享组件的元素；能用 `:not()` 收窄就收窄。

**验证方式也记一条**：这类"元素被撑变形"的问题，无障碍树里的 `Frame` 宽度就是证据
（坏的时候复选框 `width: 604`，好的时候 `width: 30`）。光看"文件改了、接口 200"发现不了。

## 反悔成本

低。配色与间距集中在 `app.css` 的 `:root` 一个块里，想回深色主要就是换这个块。但 0005 描述的
网格纹理、`//` 注释装饰、方括号 chip 属于结构性装饰，恢复需要把对应规则写回来，不是只改色值。

回滚点：`backups\agent-pre-copyedit-20260929-225203\app\static\`（改动前的全部前端文件）。

## 没有改的部分

- 页面结构与信息架构没动：还是五个页面、三列分组、来源表、表单，字段与交互一致
- 所有语义区分照旧（`取不到` 不等于"没有"、网关身份警告仍说清"你看的是谁的数"）
- `title:` 悬浮提示文案未精简（不 hover 看不见，不构成视觉杂乱）
