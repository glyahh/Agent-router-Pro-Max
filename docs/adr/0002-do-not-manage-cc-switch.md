# 桌面控制台不接管 CC Switch

这台机器上另有一个 CC Switch（`D:\cc-switch\`，监听 15721），管理 Claude Code / Gemini 等客户端的供应商切换，有自己的 SQLite 库（39MB）。

两边功能看起来重叠（都在管"AI 供应商"），合并成单一入口很诱人。但 CC Switch 的数据库是它自己的运行时状态，外部写入会踩到它的并发假设；而本项目的所有配置都在 `config.yaml` 与 `routing-plan.json` 两个文件里，走的是网关自己的管理 API。

结论：控制台只管 8317 网关和 8318 自身。不读不写 CC Switch 的库，也不代管它的进程。代价是用户有两个入口，换来的是两边都能独立升级和回退。
