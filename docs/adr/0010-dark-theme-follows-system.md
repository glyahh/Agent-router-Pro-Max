# ADR-0010：补一套跟随系统的深色主题（浅色仍是浅色系统下的那一套）

- 状态：**已采纳**（2026-09-30）
- 相关：ADR-0007（浅色留白风格）、ADR-0009（无原生标题栏 + Mica）、
  [DEV-RULES.md](../DEV-RULES.md) A4/B1/B4
- 证据：[evidence-dark-theme-render.txt](../evidence-dark-theme-render.txt)
- 与 0007 的关系：**不是反转**。0007 定的浅色设计在浅色系统下一位没改（证据 §3 逐项核对
  11/11 一致），本 ADR 只增加"系统深色时用另一套令牌"这一条。

## 1. 起因

ADR-0009 把窗口做成了无原生标题栏 + Mica 透底。Mica 的颜色跟随**系统**主题，而 Prism 只有
浅色 UI（ADR-0007）。在这台机器上系统是深色（`AppsUseLightTheme=0`），于是深色 Mica 从
半透明顶栏（`.72` 的白）底下透上来，整体偏灰 —— 观感"脏"。ADR-0009 当时把这条写成已知
取舍，并把选择权留给用户；用户选了**补一套深色主题**。

## 2. 决策

### 2.1 用 Python 读系统主题，不用 `@media (prefers-color-scheme)`

两条路都能做，选的是**可断言**的那条：

| 方案 | 判断 |
|---|---|
| CSS `@media (prefers-color-scheme:dark)` | **不用**。WebView2 的 `PreferredColorScheme` 默认值到底跟不跟系统，本机**没有实测过**；`pywebview` 也没有设置它。押在这上面就等于把主题正确性押在一个未验证的行为上，而且它不好测（Chromium 无头能模拟，但模拟的不是 WebView2 的实际取值）。 |
| `server.py` 读注册表 `AppsUseLightTheme` | **采用**。权威、可断言（`GET /api/theme` 直接能测），并且顺带解决了"首屏闪白"。 |

### 2.2 三层落地

1. **首屏不闪**：`_serve_static()` 服务 `index.html` 时把占位 `data-theme="light"` 替换成
   实际主题 —— 定长字节替换，找不到占位就原样端出去（老 index.html 不会因此 500）。
   这样第一帧就是对的，不靠 JS。
2. **跟随变化**：新增 `GET /api/theme`，`app.js` 每个轮询周期（`POLL_MS`，5 秒）跟一次。
   用户在 Windows 设置里换主题，最迟一个周期后切过来，**不必重启 Prism**。
   主题读不到时不打扰用户（不是关键路径）。
3. **配色**：`app.css` 的 `html[data-theme="dark"]{}` 覆盖 `:root` 的同名令牌，
   **令牌名与浅色一一对应，只换值** —— 组件层一行都不用改。

### 2.3 顺手做的一件事：把组件层的硬编码色值令牌化

A4 早就规定"颜色一律走令牌，不写魔法值"，但组件层仍散着 **11 处**硬编码（滚动条
`#D8D8D8`、顶栏/状态栏 `rgba(255,255,255,.72)`、遮罩 `rgba(0,0,0,.28)`、骨架屏渐变的两个
灰、日志搜索高亮 `#FFE9A8`、两处弹层阴影、开关旋钮阴影、关闭按钮的 `#C4342B`）。
深色主题要求它们整体换一套，所以这次一并收进令牌（`--topbg` / `--scroll` / `--scrollh` /
`--scrim` / `--pop` / `--pop2` / `--skel1` / `--skel2` / `--hl` / `--knob-shadow`）。
**浅色下的值与原来逐字相同**，所以这不是行为改变，是把 A4 的欠账还上。

## 3. 深色配色的来历

- 底色 `#1B1B1B` 一档档往上到 `#2E2E2E`，与浅色"白 → 极浅灰"的层次同构（0007 的分层思路）。
- 强调色反转：浅色是"近黑实心按钮 + 白字"，深色是"近白实心按钮 + 深字"
  （`--accent:#F0F0F0` / `--onaccent:#141414`）。这是 Codex / VS Code 那类深色客户端的做法。
- 状态色保留语义、提高明度、底色改成深色调的药丸底（`--okbg:#17231C` 等），
  避免浅色药丸底在深色背景上"发亮"。
- 实测对比度见证据 §2：正文 6.36，远高于 4.5；低对比只出现在**浅色侧本来就低**的
  第三档灰与状态药丸上，本次没有改动浅色。

## 4. 后果

**好的**：

- 系统深色时观感与 Codex 一致，Mica 透上来正好接得住（深色半透明顶栏 + 深色 Mica）。
- 浅色系统下与改动前**逐字相同**（证据 §3），不引入视觉回归。
- 主题是个可测的 HTTP 值（`/api/theme`），不是靠猜渲染引擎的行为。

**代价 / 风险**：

- `server.py` 多了一个 `winreg` 读（非 Windows 或键缺失时回落 `light`）。**不缓存**：
  一次 `OpenKey + QueryValueEx` 是微秒级，换来的是不必重启就能跟随。
- **没有在真的 WebView2 窗口里看过**（证据 §5）：Chrome 无头与 WebView2 同为 Chromium，
  但不是同一个宿主；Mica 的实际色调整轮未验。
- **系统主题热切换未实测**：机制上支持，但没在 Prism 开着时真改一次 Windows 主题。
- 只有静态快照：hover / focus / disabled / 对话框 / 命令面板 / 轻提示的深色取值没验。
- 没有"手动指定主题"的设置项。本轮就按用户要求的"跟随系统"做；将来要加
  「跟随系统 / 浅色 / 深色」三态，落点是设置页的"应用"那一组，加一个 `/api/theme`
  的写入口即可。

> **2026-09-30 晚补记（本 ADR 之后的另一轮改动）**：那个三态设置**已经加上了** ——
> `settings.json` 的 `app.theme_mode`（默认 `system`），设置页有分段控件，`server.py`
> 新增 `effective_theme()`（显式 light/dark 优先，否则回落本 ADR 的 `system_theme()`），
> `/api/theme` 因此同时返回 `theme`（有效）与 `system`（原始）。本 ADR 的机制没被推翻，
> 它成了底层的判定函数；上面的"没有设置项"一句**已过时**，但保留原文以留痕。
> 三态是前端那轮改动引入的，没有为它单独写 ADR。

## 5. 被否决的方案

- **关掉 Mica 用纯色**：用户没选（那是另一条候选路）。而且 Mica 是 ADR-0009 特意做出来的，
  为了绕开浅色 UI 的灰调而把它关掉，等于把窗口改造白做。
- **只把顶栏透明度调低来"压掉"灰调**：治不了根 —— 深色 Mica 是整窗的，底下的
  `--bg` 不透明，透上来的只有顶栏/状态栏那两条，怎么调都是"浅色 UI 配深灰条"。
- **在页面里复制一套深色样式**（而不是覆盖令牌）：直接违反 DEV-RULES A1；而且五个页面
  各有一份组件 CSS，复制必然漂移。
