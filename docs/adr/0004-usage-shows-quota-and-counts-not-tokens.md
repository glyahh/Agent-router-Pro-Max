# 用量页只展示配额信号与请求计数，不去解析 token

网关能提供两种数据，语义完全不同：

- **官方 OAuth 账号**：随响应头带回来的配额信号——已用百分比、窗口长度、重置时间。只覆盖官方账号。
- **第三方来源**：请求成功/失败次数，10 分钟一个桶。**没有 token 数。**

二进制里确实有 `prompt_tokens` / `completion_tokens` 的解析代码，但没有任何接口把它吐出来。

曾考虑打开网关的 request-log 开关，落全量请求后自行解析 token 明细。决定不做：该开关默认关闭，打开后记录的是完整请求内容（体积与隐私代价都不小），而日常真正要看的是"额度还剩多少"——官方配额信号已经直接给出，比 token 数更贴近决策。

代价：看不到 token 消耗曲线。如果将来确实需要，再评估开启 request-log 的存储与脱敏方案，届时这条 ADR 要改。

顺带一提，这条决定了"用量"页的版式：上半部是官方账号的配额条与重置倒计时，下半部是各来源的请求计数曲线，两者不能画在同一张图上。
